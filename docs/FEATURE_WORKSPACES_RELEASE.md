## Shared interface and weather

All six cards open a common accessible dialog with Back/Close, feature navigation, focus restoration and one reused Leaflet map. Desktop uses split content/map; tablet/mobile adapt to a single column. Resize/rotation/tab-return/feature-return invalidate the visible map. Map layers and async results are scoped so another feature cannot receive a late journey or stop selection. Navigation preserves explicitly selected route/stop/origin/destination; language reloads revalidate one-use tab-stored IDs, never store raw GPS for that handoff. Offline/recovery messages are visible inside the workspace. Touch targets and native map zoom controls have 44px minimum height in the relevant controls.

The Milwaukee imagery, skyline, bus, bats, palette, fonts and Abhiraj Bandari creator section remain. Header weather uses the existing real Open-Meteo current-condition request with WMO codes and provider is_day. Clear/mainly clear, cloud, rain/drizzle, snow, storms (including code 97), fog, night and unknown/unavailable are mapped. Unknown day/night does not fabricate sunshine. Temperature, valid-time metadata and source credit are supplied; stale/failure clears the value and old timestamp. Updates run every 15 minutes while visible/online. Subtle effects pause when hidden and respect reduced motion. General weather never establishes stop/sidewalk safety.

WMO/is_day semantics were checked against [Open-Meteo documentation](https://open-meteo.com/en/docs). Conditions are provider/model data, not verified sidewalk observations. Provider usage, licensing and production traffic terms still need operator approval. OpenStreetMap copyright/license and weather credits are linked visibly; this is not a legal-compliance certification.

## AI boundary, security, privacy and cost

The chosen integration is native browser WebRTC with a Flask-mediated SDP exchange to OpenAI Realtime `/v1/realtime/calls`, following [official OpenAI WebRTC documentation](https://developers.openai.com/api/docs/guides/voice-webrtc). No Agents SDK package or public private-key endpoint was added. Compatibility was checked in documentation; actual paid transport/model compatibility was **not** tested with an account.

Seven tools only: find_nearby_stops, get_stop_departures, get_live_buses, plan_journey, get_service_alerts, get_reliability_status and open_feature. Server-side names, fields, types, IDs, coordinates, radius, cursors, dates and navigation values are validated. There is no arbitrary URL/file/SQL/moderation tool. Source/report text is rendered as text and treated as untrusted data; model factual grounding and prompt-injection resistance still require real-provider evaluation before enablement.

Live voice defaults disabled. Activation requires OPENAI_API_KEY in the server secret manager, AYO_REALTIME_ENABLED=1, AYO_VOICE_SPEND_APPROVED=1 and a trusted server AYO_VOICE_AUTHENTICATE adapter. Identity must not come from an untrusted request header. Persistent admission limits are 20 global starts/day and three/account/day, one provider setup at a time, bounded HTTP timeout and max_output_tokens 256. Failed starts conservatively consume admission. The browser stops local capture after 180 seconds or stop/close/hide/offline/disconnect. **Client duration limits are not tamper-proof financial limits.** A provider spend cap and server-controlled session supervision/termination must be provisioned and accepted before public paid use; neither an authentication account service nor that operational supervision is deployed here.

No application-server audio/transcript recording was added. Typed history is page-local; provider processing/retention requires operator review and is explained in EN/ES privacy content. Public transit tools share existing rate limits and two planner slots. HTTPS/host/origin controls, private SQLite, encrypted push/backups, moderator isolation and redacted production logging remain. Dependency advisory results are time-limited evidence, not penetration-test certification.
